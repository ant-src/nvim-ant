1. Introduction                                             *ant-introduction*

Highlighting, indentation, the `ant lsp` language server, and the `ant dap`
debugger for Ant files (`*.ant`). Needs Neovim 0.11 or later and `ant`:
>sh
    go install github.com/ant-src/ant/cmd/ant@latest
<
The plugin needs no setup. |:checkhealth| ant says what it found.

Neovim gives Apache Ant's build.xml the filetype ant too; this plugin leaves
`.xml` files alone.

==============================================================================
2. Options                                                       *ant-options*
                                                                       *g:ant*
>lua
    vim.g.ant = {
      path = nil,  -- the ant executable; nil looks on PATH, in $GOBIN,
                   -- in the bin directory of `go env GOPATH`, and ~/go/bin,
                   -- passing over Apache Ant's launcher
      lsp = true,  -- start ant lsp for Ant files
      dap = true,  -- register ant dap with nvim-dap, when it is installed
      completion = true,  -- enable |lsp-completion| for ant lsp
    }
<
                                                                 *ant.setup()*
require("ant").setup({opts}) sets the same options, for plugin managers that
call it.

3. Commands                                                     *ant-commands*

:Ant run [args]                                                     *:Ant-run*
        Save the current file and run it with `ant run` in a terminal below,
        with [args] after the file.

:Ant debug [args]                                                 *:Ant-debug*
        Save the current file and debug it with `ant dap`. Needs nvim-dap.
        In a test file, it debugs every test of the file.

:Ant test [pattern]                                                *:Ant-test*
        Save the current file and run its tests with `ant test` in a
        terminal below; from `name.ant`, the tests of `name_test.ant`.
        [pattern] is passed as `-run`, a regular expression for each
        `/`-separated level of the test names.

:Ant test-all [pattern]                                        *:Ant-test-all*
        Run `ant test` on Neovim's working directory, every test file under
        it, with [pattern] as `-run`.

:Ant test-nearest                                          *:Ant-test-nearest*
        Run the test or subtest the cursor is in. A subtest whose name is not
        a literal is passed over for the test around it.

:Ant debug-nearest                                        *:Ant-debug-nearest*
        Debug the test or subtest the cursor is in. Needs nvim-dap.

:Ant restart                                                    *:Ant-restart*
        Stop the language servers and start them again, looking for `ant`
        afresh.

:Ant log                                                            *:Ant-log*
        Open the LSP log.

|:make| runs `ant check` on the current file.

==============================================================================
4. Language server                                                   *ant-lsp*

The configuration is named "ant" (|vim.lsp.config()|), so any field can be
changed with:
>lua
    vim.lsp.config("ant", { ... })
<
A server starts for each project, the nearest directory with `.git` above a
file, or the file's directory. Definition of a prelude name opens the prelude,
`ant:/prelude.d.ant`, read-only, served by the server, where hover and
definition work as in any file.

Completion is enabled with |vim.lsp.completion.enable()|, without
autotrigger, so that accepting an item from |i_CTRL-X_CTRL-O| with CTRL-Y
expands its snippet: `xs | filt` becomes `xs | Array.filter()`. Set
`completion = false` to leave completion to another plugin.

Markup elements and attributes are highlighted through the groups
`@lsp.type.element.ant` and `@lsp.type.attribute.ant`, linked to `@tag` and
`@tag.attribute` by default.

==============================================================================
5. Debugging                                                         *ant-dap*

With nvim-dap installed, the adapter "ant" and the configuration "Debug Ant
file" are registered when the first Ant file opens. A configuration takes:

    program      the file to run (required)
    args         the program's arguments
    cwd          the working directory; the program's directory by default
    env          environment variables set over Neovim's
    stdin        a file whose contents are the program's standard input
    stopOnEntry  stop before the first statement of the program

    test         in a test file, the `-run` pattern of the tests to run

A relative cwd is resolved against Neovim's working directory, a relative
program against cwd (or Neovim's working directory without one), and a
relative stdin against the program's working directory.

==============================================================================
6. Tests                                                            *ant-test*

Test files end in `_test.ant`; in them, `test "name" { ... }` is highlighted
as a declaration. The language server puts two code lenses above each test,
and each subtest whose name is a literal: "run test" runs it with `ant test`
in a terminal below, and "debug test" debugs it with nvim-dap. Run the lens
on the cursor's line with |vim.lsp.codelens.run()|, for example:
>lua
    vim.keymap.set("n", "<leader>l", vim.lsp.codelens.run)
<
The lenses' commands, `ant.test.run` and `ant.test.debug`, are in the
`commands` of the "ant" configuration. See also |:Ant-test|.
